🧪 User testing scenarios
5 tasks · 5 participants · target success rate ≥ 80%
T1
Discover & book a service
Task: Find "Bridal Makeup" on Explore, view vendor profile, pick 12 Nov, add to cart, checkout with a coupon. Success metric: booked < 5 taps wasted, 1 retry max.
T2
End-to-end checkout (guest)
Task: Add a subscription product to cart, check out as guest. Verify: no 403 (JWT malformed), all 5 address fields complete, order shows in "Your Orders".
T3
Search across product types
Task: Search "property", "makeup", and "bag of rice". Verify all product types (physical / booking / service / sub) appear in results and "All products" on Explore loads.
T4
Vendor workflow
Task (vendor account): 1) Check today's orders on dashboard; 2) Generate a pay-link QR for a custom ₦45k booking; 3) Initiate a withdrawal.
T5
Profile → My Account parity
Task: Edit billing address, confirm it appears the same in Profile → Orders & My Account tabs. Then change password and confirm re-login works.
Design decisions log (highlights)
• Orange #e67e14 is the single brand accent with 44-contrast AA+ text.
• All tap targets ≥ 44×44 dp (WCAG 2.1 AA); 8 dp spacing; 16+ dp on chips/bottom nav.
• Bottom nav fixed at 4 tabs only (Home / Explore / Cart / Profile); orders live in Profile → Your orders.
• Platform parity: iOS uses Cupertino overrides inside Material shell; Android uses M3 ripple + status bar edge-to-edge.
• Booking/vendors/livestream rendered in WebView bridges to guarantee parity with the web marketplace.
• App-update dialog shown on cold start when vendor-api reports a newer version code.
